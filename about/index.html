About · 关于这份清单

我们只写能核实的事。

这是一个中文的开源项目与互联网工具发现站。它不是排行榜，也不是导航站收录表，而是一份有人读过 README、打开过官网、然后写下来的清单。

怎么选的

选题没有算法。判断标准就三条：它是否解决了一个具体问题；现在是否还能跑起来；中文读者是否有必要知道它。 热门不是入选理由，冷门也不是。每个项目的「编辑备注」写的都是我们自己会怎么用它。

我们不接受付费收录，也不把 Star 数当成质量分。站内没有埋点，「本周热门」只看两件事：仓库 Star 规模与最近推送时间——算法写在scripts/build-data.mjs 里，可以复核。

数据从哪来

  • 仓库元信息：GitHub REST API 抓取的公开数据（Star、Fork、许可证、最近推送、Topics），每条记录都带抓取时间。
  • 中文介绍：分两种来源，页面上分得清楚——编辑读完 README 后手写的条目，以及机器自动整理的条目。
  • 自动收录：每天由 GitHub Actions 搜索新项目、抓取 README 与官网截图，再用规则（或可选的模型）生成中文条目，自动发布。 这类条目带「自动收录」标记，详情页会说明「未经人工校对」，contentBasis 写明依据的 README 与字数。
  • 截图：用无头浏览器从项目官网或演示站实时抓取，页面底部标注抓取日期。抓不到就用带标注的占位图，不拿别的图冒充。
  • 未知项：许可证未声明、Star 取不到、演示链接不存在——一律显示「未知」，并在详情页说明原因。

许可证与署名

每个项目的代码、文档、名称与商标归其作者所有。本站只摘录公开 README 的内容并注明来源，不复制源码，也不代表作者背书。 转载本站的中文介绍请保留项目名、原作者与原始仓库链接。

若你是项目作者，希望修改或移除某条介绍，请按贡献流程提交，我们会在下一期处理。

怎么贡献

这个站点的内容全部是纯文本数据文件，改动一个 JSON 就能提 PR：

  1. 推荐一个项目：在 data/sources.json 里加一行 { "slug", "repo", "category" }，运行 npm run data:fetch -- <slug>。
  2. 补全中文介绍：复制 data/projects/_template.json，按 README 填写 features、audienceFor、setup，并在 contentBasis 里写明依据。
  3. 跑 npm run data:check 与 npm run build，两个都过了再提 PR。

详细步骤、导入脚本、更新与部署说明都在 仓库 README 的「内容维护」「数据更新」「部署」三节。也可以直接在 GitHub Issues 里提建议，或到 作者 𝕏 留言。

常见问题

为什么有的项目没有 Star 数？

抓取时 API 额度用完或仓库被限流，我们不会用「约」「10k+」这类写法补上，直接写未知，并在下一次刷新时补。

为什么有的项目显示「许可证未知」？

GitHub 没有识别到标准许可证文件。部分项目使用自定义条款（例如 Open WebUI、MetaMask），我们会读 LICENSE 原文并在详情页写出限制。

收藏会同步吗？

不会。收藏只存在当前浏览器的 localStorage 里，可以导出 JSON / Markdown 自行迁移。

介绍是 AI 写的吗？

初稿可以由脚本从 README 生成，但发布前必须人工改写并标注依据；页面上「内容依据」一栏就是给读者核对用的。
